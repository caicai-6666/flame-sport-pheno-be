# 鉴权逻辑描述 v1

## 目标

当前阶段先实现后端内部的基础鉴权链路：

1. 前端通过 `/auth/login` 提交 `auth_code`。
2. 后端根据 `auth_code` 获取用户 ID。
3. 后端校验该用户是否存在于 `user` 表。
4. 校验通过后，将 `auth_code -> user_id` 写入服务内存缓存。
5. 后续受保护接口从请求头 `Authorization` 中读取 `auth_code`，再从缓存中解析出 `user_id`。

当前项目访问人数较少，暂时不引入 Redis，使用进程内字典作为认证缓存。

---

## 当前实现范围

当前版本已经实现：

- `/auth/login` 登录接口
- 基于 MySQL `user` 表的用户存在性校验
- 服务内存认证缓存
- 缓存过期时间
- 缓存访问续期
- 定时清理过期缓存
- 通过 FastAPI `Depends` 对受保护接口做鉴权

当前版本暂未实现：

- 调用外部系统校验真实 `auth_code`
- 角色权限控制
- 多实例服务之间的缓存共享
- refresh token 机制

## 登录流程

接口：

```http
POST /auth/login
Content-Type: application/json

{
  "auth_code": "xxx"
}
```

当前测试阶段，后端暂时将传入的 `auth_code` 直接视为 `user_id`。

对应代码位置：

```text
app/services/auth_service.py
```

当前临时逻辑：

```python
async def _resolve_user_id_from_auth_code(self, auth_code: str) -> str:
    """测试阶段暂时将 auth_code 视为用户 ID；后续替换为外部接口调用。"""
    return auth_code
```

生产阶段需要替换为：

```text
auth_code -> 调用外部系统 -> 获取真实 user_id
```

拿到 `user_id` 后，后端会查询 `user` 表：

```text
user.id = user_id
```

如果用户存在，则写入认证缓存：

```text
key   = auth_code
value = user_id
```

并返回：

```json
{
  "auth_code": "原始 auth_code"
}
```

## 认证缓存

认证缓存实现位置：

```text
app/core/auth_cache.py
```

缓存结构：

```python
dict[str, AuthCacheItem]
```

其中：

```text
key = auth_code
value = AuthCacheItem(user_id, expires_at)
```

`AuthCacheItem` 当前包含：

```python
user_id: str
expires_at: float
```

---

## 缓存配置

配置位置：

```text
.env
```

当前配置：

```env
AUTH_CACHE_TTL_SECONDS=7200
AUTH_CACHE_CLEANUP_INTERVAL_SECONDS=300
```

含义：

- `AUTH_CACHE_TTL_SECONDS`：单个 token 的有效期，当前为 7200 秒，即 2 小时。
- `AUTH_CACHE_CLEANUP_INTERVAL_SECONDS`：后台清理过期缓存的间隔，当前为 300 秒，即 5 分钟。

---

## 访问续期逻辑

当前缓存采用滑动过期策略。

只要用户在 token 有效期内访问受保护接口，后端就会自动续期：

```text
新的过期时间 = 当前时间 + AUTH_CACHE_TTL_SECONDS
```

示例：

```text
12:00 登录成功，token 过期时间为 14:00
13:30 访问受保护接口，token 过期时间刷新为 15:30
15:00 再次访问，token 过期时间刷新为 17:00
```

如果 token 已经过期，则不会续期，会删除该缓存并返回未登录状态。

## 定时清理逻辑

服务启动时会启动一个后台任务，定时清理过期 token。

启动位置：

```text
main.py
```

当前通过 FastAPI lifespan 管理：

```python
@asynccontextmanager
async def lifespan(application: FastAPI):
    """应用生命周期：启动时初始化目录和后台任务，关闭时清理后台任务。"""
```

启动时：

```python
start_auth_cache_cleanup_task()
```

关闭时：

```python
await stop_auth_cache_cleanup_task()
```

即使后台任务尚未清理某个过期 token，接口访问时也会再次检查过期时间，因此过期 token 不会继续有效。

## 受保护接口鉴权

鉴权依赖实现位置：

```text
app/core/security.py
```

核心逻辑：

1. 从请求头读取 `Authorization`。
2. 如果没有 `Authorization`，返回 `401`。
3. 如果有 `Authorization`，使用其作为 `auth_code` 查询内存缓存。
4. 如果缓存不存在或已过期，返回 `401`。
5. 如果缓存有效，返回对应的 `user_id` 给业务路由使用。

请求头格式：

```http
Authorization: xxx
```

当前没有强制使用：

```http
Authorization: Bearer xxx
```

也就是说，前端直接把 `auth_code` 原样放入 `Authorization` 即可。

---

## 路由使用方式

当前受保护接口示例：

```text
app/routers/image.py
```

示例：

```python
@router.get("/avatar")
async def get_avatar(
    user_id: str = Depends(get_current_user_id),
    session: AsyncSession = Depends(get_session),
):
    """校验 Authorization 后，返回当前用户可访问的头像图片。"""
```

`get_current_user_id` 会完成鉴权，并将解析出的 `user_id` 注入到路由函数。

业务代码不需要自己解析请求头。

## 未登录或登录过期

如果请求头缺少 `Authorization`：

```http
401 Unauthorized
```

响应：

```json
{
  "detail": "缺少 Authorization，请先登录"
}
```

如果 token 无效或已过期：

```http
401 Unauthorized
```

响应：

```json
{
  "detail": "登录状态无效或已过期，请重新登录"
}
```

前端收到 `401` 后，应跳转到登录页或重新执行登录流程。

## 当前头像接口链路示例

前端请求：

```http
GET /image/avatar
Authorization: bb123456
```

后端处理流程：

```text
Authorization -> auth_code
auth_code -> auth_cache -> user_id
user_id -> 查询 user 表 -> avatar_url
avatar_url -> 拼接本地头像路径 -> FileResponse 返回图片
```

当前测试数据示例：

```text
user_id = bb123456
avatar_url = /james.jpg
最终文件路径 = assets/images/avatar/james.jpg
```

## 后续生产阶段需要调整

后续接入真实外部登录系统时，主要修改点是：

```text
app/services/auth_service.py
```

将当前临时逻辑：

```python
return auth_code
```

替换为：

```text
调用外部系统校验 auth_code，并返回真实 user_id
```

其他缓存、依赖注入、受保护接口逻辑可以保持不变。
