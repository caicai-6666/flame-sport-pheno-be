# 文档维护说明

所有 Markdown 文档的结构、格式和表达统一遵循[项目文档撰写规范](../document-style.md)。本文档只说明功能变更与文档同步范围，不重复定义排版规则。

## 新接口开发时

新增接口后需要同步更新：

```text
description/api/{router}.md
description/business/{相关业务}.md
```

如果接口涉及新表或表结构调整，再由用户明确要求后更新：

```text
description/db/
```

---

## 文档职责边界

`api` 文档回答：

```text
接口怎么调用
需要什么参数
返回什么结构
可能有哪些错误
```

`business` 文档回答：

```text
为什么要这样校验
状态如何流转
涉及哪些表
哪些规则跨多个接口共享
```

`dev` 文档回答：

```text
如何本地运行
如何准备资源文件
如何构造 mock 数据
文档如何维护
```

---

## 命名建议

- 文件名使用小写英文；除下述 DB 文档外，多单词名称使用下划线。
- API 文档按路由命名，例如 `project.md`。
- 业务文档按流程命名，例如 `proof_upload.md`。
- DB 文档按表名命名，并以连字符分隔单词，例如 `proof-record.md`。

新增、删除或重命名文档时，还需同步更新[项目文档地图](../README.md)。
