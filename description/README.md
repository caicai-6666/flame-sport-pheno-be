# 项目描述文档

本文档目录用于统一存放后端项目的描述性资料。

## 目录结构

```text
description/
  db/        数据库表设计文档
  api/       接口契约文档
  business/ 业务流程和规则文档
  dev/      本地开发、测试和维护文档
```

## 维护规则

- `db/`：存放数据库设计文档，只作为数据库设计依据阅读；除非明确要调整表结构，否则不在接口开发中顺手修改。
- `api/`：描述接口如何调用，包括请求方式、参数、响应、错误码和鉴权要求。
- `business/`：描述跨接口、跨表的业务流程和状态规则。
- `dev/`：描述本地运行、测试数据、文件存储和文档维护方式。

接口开发时建议按顺序阅读：

1. `description/db/` 中相关表设计。
2. `description/business/` 中相关业务流程。
3. `description/api/` 中对应接口契约。
4. 代码中的 `router -> service -> repository -> model` 实现。
